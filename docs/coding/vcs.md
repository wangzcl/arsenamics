# 版本控制（Git）

本节中我们介绍 Git，版本控制系统的绝对主流，以及其与相关软件的集成。

## 为什么需要 Git

一般的教程在介绍为什么要使用版本控制系统的时候，都会用写论文来举例子：假设你写了第1版、第2版、第2.5版，最终版，最终版2等等，同时又要保留前面的版本，防止里面有些内容需要加回去。很快这么多文件就会变得混乱，而使用版本控制系统能优雅地解决这个问题。

不过如果你的论文是 MS Word 这样的二进制文件，其实这个说法并不严谨。Git 这类版本控制系统主要还是针对文本文件（如代码脚本）设计的。写代码是一个不断试错的过程，其中的混乱程度更胜于写论文，因此熟悉版本控制会带来很大便利。

话虽如此，许多云盘（如 Onedrive 和 Dropbox）都带有恢复文件旧版本的功能，如果只是个人进行一些小体量的论文或代码工作，这可能也勉强够用了。为什么要费劲学习复杂的 Git 呢？

只有当多人协作开发项目时，Git 的力量才真正体现出来，它能够让每人在自己手里的版本上独自进行编辑，然后把改动合并到一处，让多人协作和纷繁的编辑记录变得整齐、有序、可追溯。不了解 Git 的基本知识，几乎无法在 GitHub 等平台上进行有效协作（我们将在下一章节深入这一部分）。
